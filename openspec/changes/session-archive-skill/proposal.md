## Why

当前 AI 编程助手在长周期协作中缺乏对会话的结构化沉淀能力：会话结束后内容散落、无法按日期回溯、无法跨会话复用上下文。本变更提议新增一个 **会话归档管理 SKILL**，让助手在首次使用时自动建立归档目录结构，并支持把当前会话导出为 Markdown 文档、记录执行环境（Agent / LLM 标识）、标注完成状态、浏览与重新加载历史归档会话，从而形成可持续积累的个人/团队会话知识库。

## What Changes

- 新增一个可复用的 SKILL（技能），封装"会话归档管理"能力，供 AI 助手在对话中按需调用。
- 首次调用时执行文档结构检查：在对应 agent 目录下创建 `session-archive/` 根目录，并按日期（`YYYY-M-D`）建立子文件夹。
- 支持将当前会话保存为 Markdown 文档到 `session-archive/<日期>/<会话名>.md`：
  - 若用户未指定会话名，则基于内容自动总结生成文件名（例如 `图片上传.md`）。
  - 在归档文档头部记录当前 Agent 名称与 LLM 模型（例如 Claude Code、GLM-5.2）。
  - 询问用户当前会话是否已完成，据此标记归档状态为「已完成」或「进行中」。
- 支持读取 `session-archive/` 目录，汇总各归档会话的标题、日期、Agent/LLM、状态等摘要信息。
- 支持选择任一归档会话，将其内容重新加载到当前会话上下文中以便继续。

## Capabilities

### New Capabilities
- `session-archive`: 会话归档管理 SKILL，涵盖目录初始化检查、会话导出为 Markdown、执行环境（Agent/LLM）记录、完成状态标注、归档浏览与重新加载。

## Impact

- 新增产物：一个 SKILL 定义文件（含 SKILL.md / 指令说明及可能的辅助脚本）。
- 文件系统影响：在 agent 工作目录下生成 `session-archive/<日期>/` 目录与若干 `.md` 文档。
- 依赖：仅依赖本地文件系统操作与助手自身的会话/上下文访问能力，无外部服务依赖。
- 风险：归档文档可能包含敏感对话内容，需在 SKILL 中提示用户注意，且不应将归档写入受版本控制或共享的敏感路径。
