# resume-versions Specification

## ADDED Requirements

### Requirement: 多版本生命周期
系统 MUST 支持创建、命名、编辑、删除、激活多个简历版本。每个版本拥有独立名称与内容，生命周期状态由激活标记表示。

#### Scenario: 创建新版本
- **WHEN** 后台用户新建一个版本并提供名称与内容
- **THEN** 新版本被保存为非激活状态，可直接编辑或后续切换激活

#### Scenario: 版本命名
- **WHEN** 后台用户为版本设置名称
- **THEN** 版本列表中显示该名称，便于区分不同版本（如「默认版本」「2026 夏季版」）

#### Scenario: 编辑历史版本
- **WHEN** 后台用户编辑一个非激活版本的内容或名称并保存
- **THEN** 该版本内容被更新，其他版本与当前生效版本不受影响

### Requirement: 单活跃版本约束
系统 MUST 保证任意时刻至多存在一个生效版本；前台简历页 MUST 仅展示当前生效版本的内容。

#### Scenario: 切换生效版本
- **WHEN** 后台用户将版本 B 切换为生效版本
- **THEN** 原生效版本 A 自动取消激活，B 成为唯一生效版本；前台刷新后展示 B 的内容

#### Scenario: 前台展示生效版本
- **WHEN** 前台简历页加载
- **THEN** 仅渲染当前生效版本内容，不展示其他版本数据

### Requirement: 版本删除保护
系统 MUST 保护版本删除操作，不允许删除当前唯一的生效版本，避免前台无数据可展示。

#### Scenario: 删除非激活版本
- **WHEN** 后台用户删除一个非激活版本
- **THEN** 该版本被删除，当前生效版本保持不变

#### Scenario: 删除生效版本被拒绝
- **WHEN** 后台用户尝试删除当前唯一的生效版本
- **THEN** 操作被拒绝并提示原因，生效版本保留

### Requirement: 版本操作反馈
系统 MUST 在版本管理的增删改、切换激活操作成功后给出明确的界面反馈（如成功提示、列表刷新），操作失败时给出可读错误信息。

#### Scenario: 操作成功反馈
- **WHEN** 后台完成新建/编辑/删除/切换激活任一操作且成功
- **THEN** 界面出现成功提示且版本列表更新为最新状态

#### Scenario: 操作失败反馈
- **WHEN** 后台操作被后端拒绝（如删除生效版本、缺少必填字段）
- **THEN** 界面出现可读的错误提示，列表状态不产生破坏性变更
