## Context

AI 编程助手在长周期协作中频繁产生有价值的对话上下文，但缺乏结构化沉淀机制：会话一结束内容即散落不可回溯，跨会话复用上下文只能靠人工复制粘贴。目标是以一个可复用的 **SKILL** 形式，让助手在对话中能够"一键归档"当前会话、并能在日后"浏览 / 重新加载"历史会话。

SKILL 运行环境为本地文件系统 + 助手自身的会话/上下文访问能力。归档根目录位于当前 agent 的工作目录下（与具体项目解耦，可跨项目复用）。目录结构约定：

```
<agent-workdir>/
└── session-archive/
    └── 2026-8-12/
        ├── 图片上传.md
        └── ...
```

每个归档文件为 Markdown，头部以 YAML frontmatter（或约定格式）记录元数据：会话名、归档日期、Agent 名称、LLM 模型、完成状态。

## Goals / Non-Goals

**Goals:**
- 首次调用自动检查并初始化 `session-archive/<日期>/` 目录结构。
- 支持将当前会话导出为 Markdown，文件名可由用户指定或自动总结生成。
- 在归档文档中记录执行环境（Agent / LLM）与完成状态（已完成 / 进行中）。
- 支持浏览归档列表并展示摘要（标题、日期、Agent/LLM、状态）。
- 支持选择归档会话并将其内容重新加载到当前会话上下文。

**Non-Goals:**
- 不做云端同步 / 多设备同步（纯本地文件）。
- 不做语义搜索 / 向量索引（仅按目录与 frontmatter 浏览）。
- 不做自动定时归档（仅由用户或显式指令触发）。
- 不处理敏感信息脱敏（仅在 SKILL 提示中提醒用户）。

## Decisions

1. **目录位置**：归档根目录放在当前 agent 工作目录下 `session-archive/`，而非项目仓库内，避免污染版本控制与业务逻辑。
   - 替代方案：放在项目 `.codebuddy/` 内 —— 会随项目绑定、不利于跨项目复用，否决。

2. **日期目录格式 `YYYY-M-D`**：与用户示例（`2026-8-12`）保持一致，便于人类阅读与文件系统排序。
   - 替代方案：ISO `YYYY-MM-DD` —— 更规范但与用户给定示例不一致，且 SKILL 提示需匹配用户习惯，采用用户示例格式。

3. **元数据记录方式**：归档 Markdown 顶部使用 YAML frontmatter，字段为 `title`、`date`、`agent`、`model`、`status`。frontmatter 既机器可读又兼容普通 Markdown 渲染。
   - 替代方案：纯文本表头注释 —— 不易机器解析，否决。

4. **会话名生成**：用户未指定时，由助手基于会话内容自动总结为简短中文文件名（去特殊字符、截断长度），并回显供用户确认/修改。

5. **状态标注交互**：保存归档后主动询问"当前会话是否已完成？"，用户确认后写入 `status: completed` 或 `status: in-progress`。

6. **重新加载实现**：将所选归档 Markdown 的会话正文（frontmatter 之后的内容）读取后作为上下文注入当前会话（如通过摘要提示或粘贴到对话），而非直接改写底层会话文件（跨平台不可行）。

## Risks / Trade-offs

- **[敏感内容泄露]** 归档可能含密钥/隐私 → 在 SKILL 提示中明确要求用户归档前自行确认，且默认不归档到共享路径。
- **[文件名冲突]** 同一天同名会话会覆盖 → 检测到同名时追加序号（如 `图片上传-2.md`）或提示用户重命名。
- **[重新加载上下文膨胀]** 大归档注入会占满上下文 → 重新加载时优先注入"摘要 + 关键结论"，并标注来源文件，由用户决定是否读取全文。
- **[跨平台路径]** Windows / macOS / Linux 路径分隔符差异 → 在 SKILL 指令中使用相对路径与平台无关写法。

## Migration Plan

- 纯新增 SKILL，无既有功能需迁移；首次调用即完成目录初始化。
- 若日后调整日期格式或 frontmatter 字段，提供一次性扫描脚本兼容旧归档（本期不实现，列入 Open Questions）。
