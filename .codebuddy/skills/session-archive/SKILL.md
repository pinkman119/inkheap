# 会话归档管理（Session Archive）

将当前会话沉淀为可回溯、可复用的本地 Markdown 知识库，并支持浏览与重新加载。

**核心目录约定**（位于"当前 agent 工作目录"下，与具体项目解耦，不写入项目仓库内）：

```
<agent-workdir>/
└── session-archive/
    └── 2026-8-12/            # 日期目录，格式 YYYY-M-D
        ├── 图片上传.md
        └── ...
```

每个归档文件为 Markdown，顶部 YAML frontmatter 记录元数据：

```yaml
---
title: 图片上传
date: 2026-8-12
agent: Claude Code        # 当前 Agent 名称
model: GLM-5.2            # 当前 LLM 模型
status: completed         # completed（已完成） | in-progress（进行中）
---
```

## 触发与首次初始化（任务 1、2）

**触发判断**：当用户表达"归档 / 保存 / 导出会话""查看归档 / 会话历史""重新加载 / 继续某个归档会话"等意图时，加载本 SKILL。

**首次调用结构检查（必须最先执行）**：
1. 解析"当前 agent 工作目录"（由运行环境提供，使用平台无关的相对路径写法，兼容 Windows / macOS / Linux）。
2. 检查 `<workdir>/session-archive/` 是否存在；不存在则创建。
3. 检查 `<workdir>/session-archive/<今天日期 YYYY-M-D>/` 是否存在；不存在则创建，已存在则直接复用。
4. 后续所有读写都基于该目录，不污染版本控制或业务逻辑目录。

> 注意：路径分隔符用运行环境的相对路径写法，避免硬编码 `/` 或 `\`。

## 会话导出为 Markdown（任务 3、4）

当用户要求保存/归档当前会话时：

1. **确定会话名**：
   - 若用户已指定（如"归档成图片上传"），采用之。
   - 若未指定，基于当前会话内容**自动总结**为一个简短中文文件名（去除文件系统非法字符 `\:*?"<>|` 与换行，长度截断到约 20 字），然后**回显给用户确认**（"我将以「图片上传」作为文件名，可修改"）。
2. **写入文件**：
   - 目标路径 `<workdir>/session-archive/<日期>/<会话名>.md`。
   - **同名冲突**：若目标已存在同名文件，追加序号（如 `图片上传-2.md`）或提示用户重命名，**禁止静默覆盖**。
   - 文件内容 = YAML frontmatter + 空行 + 当前会话正文（含用户与助手的往来要点、代码、结论）。
3. **写入执行环境元数据**（frontmatter）：
   - `agent`：当前 Agent 名称（例如 `Claude Code`）。
   - `model`：当前 LLM 模型（例如 `GLM-5.2`）。
   - `date`：归档日期（`YYYY-M-D`）。
   - `title`：会话名。
4. **完成状态标注**（保存后必须询问）：
   - 主动询问用户："当前会话是否已经完成？"
   - 用户回答"已完成" → `status: completed`；否则 → `status: in-progress`。
   - 将 `status` 写入 frontmatter（如用户中途变更，可重开文件更新该字段）。

## 归档浏览与摘要（任务 5）

当用户请求查看归档会话列表时：

1. 递归读取 `<workdir>/session-archive/` 下所有 `.md` 文件。
2. 解析每个文件的 YAML frontmatter。
3. 向用户展示摘要列表，每行至少包含：**标题 / 日期 / agent / model / status**。
   示例：
   ```
   - 图片上传 | 2026-8-12 | Claude Code | GLM-5.2 | completed
   - 数据库迁移方案 | 2026-8-11 | Claude Code | GLM-5.2 | in-progress
   ```
4. 若目录为空，提示用户尚无归档。

## 归档重新加载（任务 6）

当用户选择某个归档会话要求继续时：

1. 定位用户所选文件（如 `session-archive/2026-8-12/图片上传.md`）。
2. 读取该文件，提取 frontmatter 之后的正文作为会话内容。
3. 将正文作为上下文**注入当前会话**，并**标注来源文件路径**（"以下是来自 session-archive/2026-8-12/图片上传.md 的归档内容"）。
4. 默认优先注入**摘要与关键结论**以避免上下文膨胀；若用户明确要求全文，则注入完整正文。
5. 可提示用户：如需基于该归档继续工作，可再次"保存/归档"以更新状态。

## 收尾与提醒（任务 7）

- **敏感内容提醒**：在引导用户归档前，提示其确认会话中不含密钥、token、个人隐私等；默认归档到本地工作目录，不写入共享或受版本控制路径。
- 归档纯本地、无云端同步、无定时自动归档、无语义检索（仅按目录 + frontmatter 浏览）。

## 能力范围（与 spec 对齐）

- 目录结构初始化检查（首次自动建 `session-archive/<日期>/`）
- 会话导出为 Markdown（手动/自动命名、frontmatter 记录 Agent+LLM、完成状态标注）
- 归档浏览与摘要
- 归档会话重新加载到当前上下文

## Guardrails

- 始终先执行目录初始化检查，再读写归档文件。
- 同名文件不静默覆盖。
- 重新加载注入优先摘要，避免撑爆上下文。
- 归档前提醒用户注意敏感信息。
