## 一、待修复

| 编号 | 位置 | 问题 | 影响 | 建议 |
|---|---|---|---|---|
| P1 | `common/exception/GlobalExceptionHandler.java` | Spring 的 `NoResourceFoundException`（访问不存在的静态路径，如 `GET /api/resume`）被归入「未知异常」分支，记录 ERROR 日志并返回 **500** | 前端拿到 500 而非 404，无法区分「接口不存在」与「服务端崩溃」；日志被无意义堆栈刷屏 | 增加专用分支：`NoResourceFoundException` / `NoHandlerFoundException` → **404** + `{statusCode:404,message:"Not Found"}`，日志降为 WARN |
| P2 | `common/exception/GlobalExceptionHandler.java` | 异常统一用 `log.error("未知异常 ...")`，无法按异常类型区分级别 | 运维排查时噪音大 | 业务异常 WARN、系统异常 ERROR、404 类 INFO |
| P3 | `module/*/service/impl`（about、digitallife 等） | 部分模块尚未提供 `getQueryWrapper(XxxQueryRequest)`，列表接口仍内联构造条件 | 与开发规范「每个实体对应的 Service 都定义 getQueryWrapper」不一致 | 按模块补齐，参照 article/xiaoji 的改造方式 |
| P4 | `module/about`、`module/digitallife` | 列表接口无查询参数对象 | 后续加筛选条件时要改动 Service 接口 | 补 `AboutFootprintQueryRequest`、`ChatSessionQueryRequest` 等 |
| P5 | `frontend/src/composables/useApi.js` | 开发环境 API 基址硬编码 `http://localhost:3000/api`，端口不可配置 | 后端改端口或部署到其他环境必须改源码 | 抽成 `import.meta.env.VITE_API_BASE`，保留 3000 作为默认值 |
| P6 | `README.md` / 运行环境 | `backend-java` 与 `backend-node` 均监听 3000，切换时容易残留进程导致 `Port 3000 was already in use` | 启动失败，需人工排查 | 启动脚本前置检查端口，或给 Node 版改用 3001 |
| P7 | 数据库 | `personal_profile` 库同时存有另一个项目的 9 张表（`diary_*`、`profile_*`、`user_accounts`） | 库职责混杂，备份/迁移时易误伤 | 确认后可新建独立库 `inkheap` 并切换 `DB_URL` |

## 二、已修复

| 编号 | 位置 | 问题 | 处理方式 |
|---|---|---|---|
| F1 | `module/article`、`module/xiaoji` | `getQueryWrapper(String id)` 只支持主键查询，实际列表查询在 `findAll` 里内联构造，方法**从未被调用**（死代码），排序表达式重复两处 | 签名改为 `getQueryWrapper(XxxQueryRequest)`，`findAll` 复用；排序只在 wrapper 里定义一次 |
| F2 | 全部业务模块 | `XxxQueryRequest` 各自定义 `page/pageSize`，缺少统一排序支持 | 新增 `common/model/PageQueryRequest`，统一 `page/pageSize/sortField/sortOrder` 与兜底方法 |
| F3 | 全部业务模块 | 规范示例 `.orderBy(sortField, ...)` 直接把请求参数拼进 SQL，存在**排序字段注入** | `PageQueryRequest#resolveSortColumn(白名单)` 做字段白名单校验，非法字段回退默认排序 |
| F4 | article、xiaoji、contact、comment、category、adminuser、resume、footerlink、friendlink、homepage、siteconfig | 实体/VO 构造使用多行 `setXxx()`，冗长且易漏字段 | 实体/VO 加 `@Builder + @NoArgsConstructor + @AllArgsConstructor`，构造点改链式 Builder；保留 `copyProperties` 型派生逻辑 |
| F5 | `module/resume/entity/Resume.java` | 库内激活列名是驼峰 `isActive`，MyBatis-Flex 默认转下划线会生成 `is_active` | 字段补 `@Column("isActive")`，查询恢复正常 |
