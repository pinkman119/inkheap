# INKHEAP Java 后端方案设计（backend-java）

> 目标：在 `backend-java` 中新建 SpringBoot 工程，实现与现有 `backend-node` 功能对等的能力，使 `frontend` **零改造**即可完成切换。
> 依据：`backend-java/skills/开发规范.md`（Controller-Service-Mapper / BaseResponse / ResultUtils / BusinessException / MyBatis-Flex / SpringBoot 3.5.3）。

---

## 一、范围与目标

| 项 | 内容 |
|---|---|
| 交付物 | SpringBoot 3.5.3 + Java 21 单体服务，Maven 工程 |
| 功能对等 | 23 个业务模块 / 88 个前端调用端点（含 RSS、图片代理、SSE 聊天） |
| 数据 | 28 张表，沿用 PostgreSQL 16 + pgvector |
| 前端契约 | 路径、入参、**响应形状（items / list / 裸数组）**、错误字段 `message`、HTTP 状态码全部保持不变 |
| 非目标 | 不改前端页面逻辑、不迁移数据、不做多租户/微服务拆分、后端不渲染 Markdown |

---

## 二、现状事实（决定方案的硬约束）

1. **数据库是 PostgreSQL 16 + pgvector**（`backend-node/prisma/schema.prisma:5-8`、`docker-compose.yml:18`），`dl_vectors.embedding` 是 `vector(1024)` 原生列。
2. **后端没有统一响应包装**：No `{code,msg,data}`。接口直接返回业务对象/数组；错误体是 `{statusCode, message, error}`，前端只读 `message`（`frontend/src/composables/useApi.js:44-46`），并依赖 `res.status===401` 做登出跳转（`:36-41`）。
3. **列表形状有三套，不能统一**：`{items,total,page,pageSize,totalPages}`、`{items,total}`、`{list,total,page,...}`（仅 `GET /api/admin/xiaoji`）、以及大量裸数组。
4. **两套 JWT 共用同一 secret**：管理员 7d（Bearer）、访客 14d（cookie `user_token` 优先，Bearer 兜底）。密码策略不同：管理员 bcrypt，访客 **AES-256-GCM 可逆**（找回密码要发明文邮件）。
5. **静态资源 `/files/**` 不在 `/api` 下**（`app.useStaticAssets(...,{prefix:'/files'})`），其余端点全部带 `/api` 前缀。
6. **无后端 Markdown 渲染**，只有 RSS 的 `stripMarkdown()` 反向剥除。
7. **1 处 SSE**：`POST /api/user/digital-life/chat`，事件名 `delta` / `done` / `error`。
8. 若干隐式行为必须保留：详情 GET 有写副作用（记阅读量）、自增阅读量**不刷新 `updated_at`**、`sortOrder` 归一化、训练失效钩子、`dl_models.type` 列映射 `modelType`。

## 三、关键设计决策

### D1 数据库沿用 PostgreSQL 16 + pgvector（不上 MySQL）

- 理由：`vector(1024)` 列 + 4 列唯一索引去重（`content_views`）+ `@updatedAt` 的应用层语义，迁 MySQL 要改数据模型和向量方案，收益为零。
- 实现：MyBatis-Flex（原生支持 PG），HikariCP 连接池；`dl_vectors` 用原生 SQL，向量以 `String` 传参并 `?::vector` 强转，避免额外 TypeHandler。

### D2 规范落地方式：Controller 返回 `BaseResponse<T>`，出口处自动解包

这是本方案最关键的一条：**开发规范要求 `BaseResponse`，前端要求裸对象**，两者用一层适配解耦。

```
Controller (返回 BaseResponse<T>，符合规范)
        ↓
ResponseBodyAdvice  → 只输出 data 字段（前端契约不变）
        ↓
GlobalExceptionHandler → HTTP 状态码 + {statusCode, message}（前端错误读取不变）
```

- 成功：`ResultUtils.ok(data)` → 响应体即 `data`；`data == null` 时输出 `null`（与原 Node 行为一致）。
- 失败：`BusinessException(code, msg)` → 按 code 映射 HTTP 状态（4xxxx/5xxxx → 400/401/403/404/409/429/500），响应体 `{"statusCode":404,"message":"文章不存在或未发布"}`。
- 状态码特例表（原实现显式改成 200 的接口，Java 侧用 `@ResponseStatus(HttpStatus.OK)` 或 `ResponseEntity` 逐个对齐）：`contact` PUT/DELETE、`visit` POST、`email-auth` 全部 POST、`user/comments` POST、admin comment DELETE、chat POST。
- 占位：`knife4j` 文档中接口标注为 `BaseResponse<XxxVO>`，实际返回 `XxxVO`，在每个 `@Operation` 的 description 中注明。

> 备选（未采纳）：改前端 `useApi.js` 读 `data`。88 个端点的返回处理全部要动，回归面太大。

### D3 路由前缀：不使用 `server.servlet.context-path`，Controller 显式 `/api` 前缀

- 原因：`context-path=/api` 会把 `/files/**` 一起拖进 `/api/files/**`，破坏前端 `assetUrl()` 与 Nginx 规则。
- 做法：所有 Controller 用 `@RequestMapping(ApiPrefix.V1 + "/articles")`（`ApiPrefix.V1 = "/api"`），静态资源 `addResourceHandlers("/files/**")` 天然在根路径。
- 兼容：`/api/feed.xml`、`/api/proxy/image` 同样挂在 `/api` 下。

### D4 端口 3000（开发期零前端改动）

- `frontend/src/composables/useApi.js:11` 硬编码 `http://localhost:3000/api`，`vite.config.js` 也代理到 3000。
- 决定：Java 服务 `server.port=3000`。后续可把 BASE 抽成 `import.meta.env`，再改 8080（不阻塞本次）。

### D5 鉴权：Filter + 注解，两套 token 隔离

- `AdminJwtFilter`：解析 `Authorization: Bearer`，校验 `role != 'user'`，注入 `UserContext`（`id/username/role`），每请求校验 `admin_users.status='active'`。
- `UserJwtFilter`：先读 cookie `user_token`，再回退 Bearer；校验 `role=='user'`、`email_users.status='active'`。
- `@Auth(allow = RoleEnum.ADMIN)` 注解 + `AuthInterceptor` 声明式校验；`@CurrentUser` 参数解析器注入当前用户。
- 未登录统一 `401 + {message:"Unauthorized"}`，与前端 401 硬编码行为对齐。
- 密码：`bcrypt`（`spring-security-crypto`）校验管理员；`AES-256-GCM`（`APP_ENCRYPTION_KEY`，格式 `iv.tag.ciphertext`）加解密访客密码与模型 Key，**必须与 Node 实现字节级兼容**，否则老数据无法登录。

### D6 响应形状按接口保留，不用一刀切分页对象

- `PageVO<T>` → `{items,total,page,pageSize,totalPages}`（用 `@JsonInclude(NON_NULL)` 让 `totalPages` 按需出现）。
- `ListPageVO<T>` → `{list,total,page,pageSize,totalPages}`，**仅 `GET /api/admin/xiaoji` 使用**。
- `ItemsVO<T>` → `{items,total?}`（comments、digital-life models/messages、dashboard users）。
- 其余直接返回 `List<T>` 或实体 VO。

### D7 静态文件与上传

- 上传：`MultipartFile`，字段名 `file`，5MB 上限 + mime 白名单 `png/jpeg/gif/webp`，落盘 `files/<yyyy-MM-dd>/<uuid><ext>`，`files` 表登记返回 `{id,url,filename,size}`。
- 静态映射：`/files/**` → `${app.upload-dir}`，无鉴权，与 Node 行为一致（含 Nginx 直连）。
- 删除：删记录 + 删磁盘文件，容错（文件不存在不报错）。

### D8 直接复用现有库，不做数据迁移

- 新服务直连同一个 `personal_profile` 库，Prisma 建的表即为 Java 的实体来源。
- 不使用 Flyway 自动建表（表已存在）；仅用一份 `schema.sql` 作为字段对照文档，避免两边模型漂移。

## 七、领域模块设计

### 7.1 内容域（P1 只读 / P2 写入）

**article（表 `articles`）**
- 端点：`GET /api/articles`、`GET /api/articles/slug/:slug`、`GET /api/articles/feed`；`GET/POST/PUT/DELETE /api/admin/articles`、`PUT /api/admin/articles/reorder`、`POST /api/admin/articles/generate-summary`。
- 关键逻辑：
  - 公开列表强制 `status=published AND type='article'`；admin 列表 `status='all'` **不含草稿**（原行为 `status!=='draft'` 即强制 `published=true`，必须照抄）。
  - `categoryKey` 逗号分隔时递归展开子孙分类 key。
  - 详情 GET 记阅读量（IP + 自然日去重），返回 `displayViewCount`（有虚拟值取虚拟值）。
  - 新建时 `sortOrder = min - 1`，slug = 标题 + '-' + base36 时间。
  - 更新/删除触发数字生命训练失效。
- 返回：`ArticleVO`（实体 + `tags: string[]` + `displayViewCount`）。

**category（`categories`）**
- 端点：公开 `tree`/列表，admin CRUD + `recent`。
- 关键逻辑：树构建（`parentKey` 自关联）、`articleCount` / `articleCountWithChildren`、key 重复 409、有文章引用时禁删 409、`recent` 走 Redis 列表（不可用时按文章 `createdAt` 推导，最多 5 条）。

**xiaoji（`blogs` + `blog_categories`）**
- 端点：公开 `GET /api/xiaoji`、`/xiaoji/stats`、`/xiaoji/categories`、`/xiaoji/slug/:slug`；admin CRUD + `generate-summary`。
- 关键逻辑：`GET /api/admin/xiaoji` 必须返回 **`list`** 键；详情返回嵌套 `prev`/`next`；`photos` JSON 解析；`footprintId` 空串=解绑；相册/随笔图片数量限制。

**comment（`comments`）**
- 端点：`GET /api/public/comments`（分页 `{items,total,page,pageSize}`，无 totalPages）、`POST /api/user/comments`（需访客登录，返回新评论对象）、admin 列表 + 删除（级联回复，返回 `{deleted, cascaded}`）。
- 关键逻辑：一层盖楼（`parent_id` 只能指向同目标的顶层评论）；`friends` 目标固定 UUID；限流 5 条/分钟/用户；发评论后邮件通知被回复人（异步，失败不影响主流程）。

**view（内部，无 Controller）**
- `recordView(refType, refId, ip)`：`content_views` 唯一索引 + `INSERT ... ON CONFLICT DO NOTHING` 判断是否自增；**自增时只更新 `view_count`，不动 `updated_at`**（关键，否则首页时间线乱序）。
- 定时清理 90 天记录。

### 7.3 互动域（P3）

| 模块 | 表 | 要点 |
|---|---|---|
| contact | `contact_messages` | 公开提交 201 返回 `{id,message}`；admin 分页 `{items,total,page,pageSize}` + stats `{total,unread}` + read 标记 + 删除 |

### 7.4 统计域（P1）

- `visit`：`POST /api/visit` → `site_visits` 当日 upsert 自增 + 写 `visit_logs`；返回 `{day,count}`。
- `@Scheduled` 每日清理 `visit_logs`（180 天）、`content_views`（90 天）。

### 7.5 数字生命域（P4）

| 模块 | 表 | 要点 |
|---|---|---|
| 模型配置 | `dl_models` | `modelType` ↔ 列 `type` 必须 `@Column("type")`；`api_key_enc` 用 AES 加密，出参只给 `hasApiKey`/`apiKeyMasked`；`enabled` 切换；删除 |
| 人格 | `dl_personas` | 单条更新 8 字段 |
| 训练 | `dl_vectors` | 7 种 refType（article/blog/resume/about_*）分页列出可训练内容；train = 切块 + embedding（1024 维）+ 写入 `dl_vectors`（`ON CONFLICT` 去重）；remove = 删除向量并置 `trainType=2` |
| 对话 | `chat_messages` | `POST /api/user/digital-life/chat` 用 `SseEmitter`：先写 `delta`（逐段），结束写 `done{messageId,content}`；异常写 `error`；开流前错误返回 JSON（400/429 带 `retryAfterSeconds`/409）；RAG 检索用 pgvector `<=>` 余弦距离 top-K |
| 摘要 | 复用 `dl_models` general 模型 | `POST /api/admin/articles|xiaoji/generate-summary` 返回 `{summary}`；无可用模型 409 |

- Provider 客户端抽象：`ModelClient` 接口 + `OpenAiCompatibleClient` / `OllamaClient`，按 `provider` 字段路由；统一超时、重试、错误映射。
- 限流：Redis 令牌桶（容量 5，5/min），Redis 不可用降级放行。
- SSE 需 `X-Accel-Buffering: no` 响应头（Nginx 已关缓冲）。
- `@Async` 线程池执行 embedding 与邮件，避免请求阻塞。

### 7.6 集成域（P1）

- **proxy/image**：`java.net.http.HttpClient`（不改协议），只允许 http/https，透传 `Content-Type`，`Cache-Control: max-age=2592000`，`ACAO: *`；**补两项 Node 缺失的加固**：连接/读超时 10s、最大 10MB 截断；上游非 2xx 透传状态码，异常 502。
- **feed.xml**：`produces = "application/rss+xml;charset=utf-8"`；文章 50 + 小记 50 合并取 50；`siteUrl` 为空回退请求 Host，并输出 `X-Feed-Site-Url-Source: config|fallback|cache`；内存缓存 5 分钟，`site-config` 更新时失效；摘要 `summary || quote || stripMarkdown(content)` 截 150 码点 + `…`。

## 八、数据模型映射要点

1. 28 张表统一：`id` uuid（单例表固定字符串主键 `home`/`about`/`footer`/`site`）+ `created_at`/`updated_at`。
2. MyBatis-Flex 开启下划线转驼峰；`@Table("articles")` 显式指定表名（避免 `Article` → `article` 猜错）。
3. 需显式 `@Column` 的字段：
   - `dl_models.modelType` → `type`
   - `dl_vectors.embedding` → `vector`（实体用 `String` 或排除出实体，走 XML/原生 SQL）
   - `home_page` 的 `social_links`、`articles.tags`、`blogs.photos`：库里是 **String（JSON）**，实体用 `String` 承接，VO 层解析为对象数组（不要用 JSON TypeHandler，保持与 Node 写入格式一致）。
4. **无物理外键**，全部逻辑关联，不要加 FK 约束。
5. `@updatedAt` 语义在 Java 侧手工维护（`setUpdatedAt(now)`），禁止给 `updated_at` 加数据库 `ON UPDATE` 触发器。
6. 索引需与 Prisma 对齐（`content_views` 4 列唯一、`visit_logs`、`comments(target_type,target_id,created_at)` 等），切换前用 `schema.sql` 校验一次。

## 九、非功能设计

| 主题 | 方案 |
|---|---|
| 时区 | 所有「每天一次」以 `Asia/Shanghai` 自然日 0 点 → UTC Instant，不依赖 JVM 默认时区 |
| IP | `X-Forwarded-For` 首段 + `::ffff:`/`::1` 归一化 |
| 静态资源 | `/files/**`，文件名 `uuid+ext`，日期目录分桶 |
| CORS | `allowedOriginPatterns("*") + allowCredentials(true)`（对应 Node 的全放行 + credentials） |
| 参数校验 | `@Valid` + `@Validated`；校验失败 → 400 + 首条错误消息（前端直接展示 `message`） |
| 日志 | 请求耗时 AOP + 写操作 `@Log` 审计；敏感字段（password/apiKey）脱敏 |
| 事务 | 写多表（友链审核、简历激活、评论级联删除、sortOrder 归一化）显式 `@Transactional` |
| 缓存 | RSS 5 分钟内存缓存；分类 recent 用 Redis 列表；其余不加缓存 |
| 可观测 | `/api/public/home-page` 作为健康检查（与原 Dockerfile 一致）；`/doc.html` 提供 Knife4j |
| 优雅停机 | `server.shutdown: graceful` + SSE 连接超时 |

| **P3 互动** | comment、contact、friendlink、emailauth、dashboard | 评论发表与回复、来信提交与后台处理、友链申请审核、访客注册/登录/找回密码、看板数据 |

## 十一、回归风险清单（实现时逐条核对）

1. `GET /api/admin/xiaoji` 的键是 **`list`**，写成 `items` 会白屏。
2. `GET /api/articles/slug/:slug` 的 404 文案必须是 **`文章不存在或未发布`**（前端字符串比较决定 404 页）。
3. 阅读量自增**不得更新 `updated_at`**。
4. `GET /api/admin/articles?status=all` **不返回草稿**（原实现的反直觉行为）。
5. 前端 `useApi` 只要有 admin token 就会给**公开接口**也带 Bearer，公开接口不能因 token 非法而 401（原实现公开接口不校验）。
6. 错误体字段必须是 `message`（不是 `msg`），且 400 校验错误也必须是字符串（数组会显示 `[object Object]`）。
7. 分页字段名差异：`xiaoji.list` / 其他 `items`；部分接口没有 `totalPages`。
8. `dl_models` 的 `modelType` ↔ `type` 列。
9. 访客密码 AES-GCM 必须与 Node 兼容（`iv.tag.ciphertext`，base64 分段）。
10. 训练失效钩子：article/blog/resume/about_* 的 update/delete 必须调用 `invalidateIfTrained`。
11. `app.useStaticAssets` 的 `/files` 前缀**不带** `/api`。
12. `POST /api/contact`、`/api/public/friend-applications` 是 **201**；其余多数 POST 被改成 200，需逐条对齐。
